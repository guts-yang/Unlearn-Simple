# SimNPO 实验复现指南（2×A800-80GB）

本文档面向 **2 张 A800-80GB** 的机器，说明如何从零复现本仓库的四个子项目。目标：远程 `git pull` 后按步骤即可开跑。言简意赅，只列必要细节。方法本身的公式与代码对照见 [方法原理](方法原理.md)。

**推荐复现顺序：synthetic → TOFU → MUSE → WMDP**（由易到难、由快到慢：synthetic 分钟级验证环境，TOFU 为主实验，MUSE/WMDP 需额外数据或更长时间）。

## 1. 硬件与环境

- GPU：2×A800-80GB（7B 模型最少 2 张；1 张易 OOM）。**开跑前先 `nvidia-smi -L` 确认卡已挂载**，本机曾出现过无输出、`torch.cuda.is_available()==False` 的情况。
- 镜像：PyTorch 2.8 / Python 3.12 / CUDA 12.8（可直接复用，不必降级到 CUDA 11.8）。conda 只有 `base` 环境，四个子项目都在 `base` 里跑，不必再建 `muse` / `wmdp` 环境。
- 依赖版本红线：`transformers 4.46.3` + `huggingface_hub 0.36.2`（必须 `<1.0`）+ `datasets 5.0.1`。**不要 `pip install -U huggingface_hub`**，升到 1.x 会让所有脚本 ImportError（第 9 节第一条）。
- 磁盘（实测）：

| 挂载点 | 容量 | 可用 | 用途 |
|--------|------|------|------|
| `/`（overlay，系统盘） | 30G | ~24G | 只放代码，**不要放权重/缓存/检查点** |
| `/root/autodl-tmp`（数据盘） | 300G | ~198G | 模型、HF 缓存、数据集、所有训练产出 |

- 显存占用（TOFU 训练）：约 55GB/卡；评估阶段峰值更高，已把 eval batch 调到 8

### 1.1 数据盘目录约定

```
/root/autodl-tmp/
├── env_hf.sh            # 环境变量脚本（见 1.2）
├── huggingface/         # HF_HOME：所有模型/数据集缓存
├── TOFU_results/        # TOFU 遗忘输出（forget.yaml 的 save_dir）
├── MUSE_data/           # ← 软链 MUSE/data
├── MUSE_ckpt/           # ← 软链 MUSE/baselines/ckpt
├── WMDP_files/          # data/ 放 bio 语料，results/ ← 软链 WMDP/files/results
├── WMDP_cache/          # ← 软链 WMDP/.cache
└── logs/                # 运行日志
```

仓库里这几个目录已经做成指向数据盘的软链（`MUSE/data`、`MUSE/baselines/ckpt`、`WMDP/.cache`、`WMDP/files/results`），所以代码里的相对路径不用改，写出来的字节自动落数据盘。

### 1.2 环境变量（每开一个新 shell 都要 source）

```bash
source /root/autodl-tmp/env_hf.sh
```

内容等价于：

```bash
export HF_ENDPOINT=https://hf-mirror.com                       # 必需：本机直连 huggingface.co 超时
export HF_HOME=/root/autodl-tmp/huggingface
export HUGGINGFACE_HUB_CACHE=/root/autodl-tmp/huggingface/hub
export TRANSFORMERS_CACHE=/root/autodl-tmp/huggingface/hub
export HF_TOKEN=...        # 脚本自动从仓库根目录 .env 的 HuggingFace_token 读取
export HUGGINGFACE_HUB_TOKEN="$HF_TOKEN"
```

> `HUGGINGFACE_HUB_CACHE` 必须是 `$HF_HOME/hub`。写成 `$HF_HOME` 会绕开已有的 90GB 缓存，导致模型全部重下。

## 5. synthetic（先跑，验证环境，单卡/分钟级）

数据本地生成、模型自建，无需下载任何权重，产出全在 `synthetic/{data,models,record}/`（已 gitignore）。

**注意：四个脚本的 argparse 默认值是 `state_size=9`、序列长度 `50/40/60`、样本数 `1000/500/500`，与 `run_synthetic.sh` 和仓库里已有的产物不一致。** 参数不同会拼出不同的文件名，后一步就找不到前一步的产物，所以每一步都要带上同一组参数。

下面五条命令**每条都是完整单行**，一次粘一条执行。不要把整块一起粘进交互式终端：多行 + 反斜杠续行在粘贴时容易被终端吞掉换行、把两条命令拼在一起（会看到 `--model_type retainunlearn）rning_rate 0.0005` 这种乱码）。要整块跑就写进 `.sh` 文件再 `bash xxx.sh`。

```bash
cd synthetic
```

```bash
# 1) 生成合成数据 -> data/state_size_10_retain_20_10000_..._leakage0.2.pkl
python generate_data.py --state_size 10 --seq_length_retain 20 --seq_length_forget1 20 --seq_length_forget2 20 --num_retain_sequences 10000 --num_forget_sequences1 5000 --num_forget_sequences2 5000 --leakage 0.2 --data_dir data --seed 42 --test_size 0.2
```

```bash
# 2a) 训练 pretrain（只在 forget1 上训）-> models/.../*_pretrain.pth
python train.py --state_size 10 --seq_length_retain 20 --seq_length_forget1 20 --seq_length_forget2 20 --num_retain_sequences 10000 --num_forget_sequences1 5000 --num_forget_sequences2 5000 --leakage 0.2 --data_dir data --n_embd 128 --n_layer 4 --n_head 4 --activation softmax --batch_size 128 --epochs 5 --learning_rate 0.0005 --model_type pretrain --only_forget1 --seed 42
```

```bash
# 2b) 训练 retain 参照模型 -> models/.../*_retain.pth
python train.py --state_size 10 --seq_length_retain 20 --seq_length_forget1 20 --seq_length_forget2 20 --num_retain_sequences 10000 --num_forget_sequences1 5000 --num_forget_sequences2 5000 --leakage 0.2 --data_dir data --n_embd 128 --n_layer 4 --n_head 4 --activation softmax --batch_size 128 --epochs 5 --learning_rate 0.0005 --model_type retain --seed 42
```

```bash
# 3) 遗忘 -> models/.../*_unlearn.pth + record/.../record_kl_SimNPO_*.json（约 10 分钟）
python unlearn.py --state_size 10 --seq_length_retain 20 --seq_length_forget1 20 --seq_length_forget2 20 --num_retain_sequences 10000 --num_forget_sequences1 5000 --num_forget_sequences2 5000 --leakage 0.2 --data_dir data --n_embd 128 --n_layer 4 --n_head 4 --activation softmax --pretraining_batch_size 128 --pretraining_epochs 5 --pretraining_learning_rate 0.0005 --loss_type SimNPO --beta 1.0 --unlearning_epochs 1 --max_iterations 50 --batch_size 4 --learning_rate 0.0005 --seed 42 --use_retrain_eval
```

```bash
# 4) 评估任一模型（--model_type 可选 pretrain / retain / unlearn）
python evaluate.py --state_size 10 --seq_length_retain 20 --seq_length_forget1 20 --seq_length_forget2 20 --num_retain_sequences 10000 --num_forget_sequences1 5000 --num_forget_sequences2 5000 --leakage 0.2 --data_dir data --n_embd 128 --n_layer 4 --n_head 4 --activation softmax --batch_size 128 --epochs 5 --learning_rate 0.0005 --model_type retain
```

单卡即可（默认 `cuda:0`，加 `--no_cuda` 退回 CPU）。`unlearn.py` 支持的 `loss_type` 见 `unlearn_utils.py`：`NPO`、`NPO_KL`、`NPO_RT`、`SimNPO`、`SimNPO_KL`、`SimNPO_RT`、`grad_diff`、`grad_ascent`、`kl` 等。

已在本机跑通，参考输出（`seed 42`，供对照）：

| 步骤 | 关键输出 |
|------|----------|
| 2a pretrain | Test Loss 1.9969 |
| 2b retain | Test Loss 1.9785 |
| 3 SimNPO 遗忘后 | Retain KL 2.7427，Forget KL 3.9109（forget1 3.8795 / forget2 3.9422） |
| 4 evaluate retain | Retain KL 0.0030，Forget KL 0.4277 |

遗忘过程中 forget/retain 两侧的 KL 曲线写在
`synthetic/record/<数据参数>/<模型参数>_unlearn/record_kl_<loss_type>_beta_*_iter_*_bs_*_lr_*_seed_*.json`，
自行读这个 JSON 画图即可。两个提醒：`unlearn.py` 最后打印的 `Test_KL saved to ./models/...` **路径是错的**（代码里 print 用错了变量），文件实际落在上面的 `record/` 下；`run_synthetic.sh` 末尾调用的 `plot_evaluation.py` **上游没有随代码发布，本仓库里不存在**，别照抄那一段。

## 6. TOFU 主实验（2 卡）

### 6.1 下载起点模型（本机已完成，换机器才需要重跑）

不加 `--local-dir`，直接落到数据盘上的 `HF_HOME` 缓存，避免同一份 13GB 权重存两遍：

```bash
source /root/autodl-tmp/env_hf.sh

# 遗忘起点模型（~13GB，主实验唯一必需）
hf download locuslab/tofu_ft_llama2-7b
# tokenizer / 基座（只会拉 tokenizer 与 config，几 MB）
hf download NousResearch/Llama-2-7b-chat-hf
```

`forget.py` 用 `os.listdir(model_path)` 判断权重，**`model_path` 必须是本地目录，不能填 HF 仓库名**。缓存里的快照目录就是一个合法本地目录（里面是指向 blobs 的软链，`from_pretrained` 能正常读），拿它做 `model_path`：

```bash
ls -d $HF_HOME/hub/models--locuslab--tofu_ft_llama2-7b/snapshots/*/
# /root/autodl-tmp/huggingface/hub/models--locuslab--tofu_ft_llama2-7b/snapshots/8fa500e8f345f1dd9cfe95bb4689878c944c9cbd/
```

这个路径已经写进 `TOFU/config/forget.yaml`。换机器后快照哈希会变，用上面的 `ls -d` 取到真实路径再改 `model_path`。

> 想要一个干净独立的目录也可以 `hf download locuslab/tofu_ft_llama2-7b --local-dir /root/autodl-tmp/models/tofu_ft_llama2-7b`，代价是多占 13GB。
> 备选：从作者 [Google Drive](https://drive.google.com/drive/folders/1L47Hf813gal8RD581S3XrWHnY_0ll4y4?usp=sharing) 下载 origin 模型。

### 6.2 安装依赖

本机 `base` 环境已装好 `requirements.txt` 里的依赖（transformers 4.46.3 / huggingface_hub 0.36.2 / datasets 5.0.1 / torch 2.8），`flash-attn 2.8.3.post1` 也已装好，可直接开跑：

```bash
cd TOFU
pip install -r requirements.txt                # 已装过可跳过；里面钉了 transformers 与 hub 的版本
```

> **换机器后要装 flash-attn 的话别用 `pip install flash-attn`**：本机没有 `nvcc`（只有 torch 自带的 CUDA runtime），源码编译会直接失败。必须下预编译 wheel，步骤见第 9 节。

> `requirements.txt` 原本第一行是 `git+https://github.com/huggingface/transformers`（main 分支即 v5），已改成 `transformers==4.46.3` 并加上 `huggingface_hub[cli]>=0.34,<1.0`。装完可用第 3.5 节的版本检查确认。

### 6.3 关键配置（`TOFU/config/forget.yaml`，已改好）

| 项 | 值 | 说明 |
|----|----|------|
| `model_path` | `/root/autodl-tmp/huggingface/hub/models--locuslab--tofu_ft_llama2-7b/snapshots/8fa500e8f345f1dd9cfe95bb4689878c944c9cbd` | HF 缓存里的快照目录（数据盘）；换机器后按 6.1 重新取哈希 |
| `save_dir` | `/root/autodl-tmp/TOFU_results/2GPU_<超参拼接>` | 输出必须在数据盘；**不要**改回 `${model_path}/unlearned/...`，那会把检查点写进 HF 缓存 |
| `batch_size` | 1 | 不变 |
| `gradient_accumulation_steps` | **16** | 2 卡下 `1×16×2=32`，与论文 8 卡 `1×4×8=32` 一致 |
| `num_epochs` | 10 | 不变 |
| `lr` | 1e-5 | 不变 |
| `forget_loss` | `simnpo_grad_diff` | SimNPO 主方法 |
| `eval.batch_size` | **8** | 由 30 降低，防评估 OOM |
| `flash_attention2`（在 `model_config.yaml`） | `"true"`（上游默认，未改动） | flash-attn 已装好；若换到没装的机器，改 `"false"` 回退 SDPA 即可 |

> `num_epochs` 决定数据过几遍；全局 batch = `batch_size × accum × 卡数`。用 `accum=16` 保持全局 batch=32，使优化步数与论文一致。

## 9. 常见问题

- **`ImportError: huggingface-hub>=0.23.2,<1.0 is required ... but found huggingface-hub==1.x`**：踩过一次。`pip install -U "huggingface_hub[cli]"` 会把 hub 升到 1.x，而 transformers 4.46.3 要求 `<1.0`，于是所有 `import transformers` 的脚本（synthetic 的 `train.py`/`unlearn.py`/`model.py`、TOFU、MUSE）全部报这个错。修复：

```bash
pip install "huggingface_hub[cli]>=0.34,<1.0"     # 0.34+ 才有新版 hf 命令
```

  别反过来去升 transformers：main 分支是 v5，删掉了 `synthetic/` 用的 `from transformers import AdamW`。`TOFU/requirements.txt` 已把 `transformers==4.46.3` 和 `huggingface_hub<1.0` 钉死。
- **`libgomp: Invalid value for environment variable OMP_NUM_THREADS`**：AutoDL 镜像在 `/etc/profile.d/autodl.env.sh` 里把 `OMP_NUM_THREADS` / `MKL_NUM_THREADS` 设成了 `0`，libgomp 不接受。只是噪音不影响结果，`env_hf.sh` 已改写成 8 覆盖掉。
- **下载卡住 / `ReadTimeoutError` / 连不上 huggingface.co**：本机直连 HF 不通，必须 `source /root/autodl-tmp/env_hf.sh` 让 `HF_ENDPOINT=https://hf-mirror.com` 生效。镜像偶发超时会自动重试。
- **`ModuleNotFoundError: flash_attn`**：本机已装 `flash-attn 2.8.3.post1`，正常不会报。若换机器后重现，**不要**用 `pip install flash-attn --no-build-isolation`：那会走源码编译，需要完整 CUDA toolkit（本机只有 torch 自带的 runtime，没有 `nvcc`），8 核编上百个 kernel 要一两个小时。正确做法是下官方预编译 wheel，文件名四要素必须和本机对上（`cu12` / `torch2.8` / `cxx11abiTRUE` / `cp312`，用 `python -c "import torch;print(torch.__version__, torch._C._GLIBCXX_USE_CXX11_ABI)"` 核对）：

```bash
# GitHub release 的附件走 objects.githubusercontent.com，本机直连不通；实测只有 ghproxy.net 这个代理可用。
# 单连接约 80KB/s，256MB 要 50 分钟；用 12 个 Range 连接并行可跑到约 1.9MB/s，10 分钟内完成。
bash /root/autodl-tmp/dl_flash_attn.sh      # 并行分块下载 + 字节数与 zip 完整性校验
pip install --no-deps --no-cache-dir /root/autodl-tmp/flash_attn-2.8.3.post1+cu12torch2.8cxx11abiTRUE-cp312-cp312-linux_x86_64.whl
python /root/autodl-tmp/verify_flash_attn.py   # 校验扩展可加载、transformers 能识别、数值与 SDPA 一致
```

  `--no-deps` 是为了防止 pip 顺手改动 torch。装完保持 `flash_attention2: "true"` 即可；没装的机器改成 `"false"` 回退 SDPA，两者都是精确注意力，指标等价（实测 bf16 下最大绝对误差 0.00195，就是 bf16 的舍入量级），只差速度和显存。
- **`compute_loss() got an unexpected keyword argument 'num_items_in_batch'`**：transformers 4.46 起会给 `compute_loss` 传这个参数，`TOFU/dataloader.py` 里三个自定义 Trainer 的签名已补上并忽略它（这些类自己做 loss 归约）。
- **`TypeError: Got unsupported ScalarType BFloat16`（训练跑完、评估刚开始时崩）**：踩过一次，forget05 训练 62/62 步正常结束后崩在 `trainer.evaluate()`。原因是模型以 bf16 运行，`get_batch_loss` 得到的 loss 也是 bf16，而 **NumPy 没有 bfloat16 这个 dtype**，所以 `.cpu().numpy()` 直接抛错（同一处的 `.tolist()` 反而正常，`.numpy()` 本就是多余的绕路）。这个 bug 在执行路径上连着三处，只改第一处会在十秒后崩在下一处，已全部补 `.float()`：

  | 文件 | 函数 | 字段 |
  |---|---|---|
  | `evaluate_util.py` | `get_all_evals` | `avg_gt_loss` |
  | `evaluate_util.py` | `eval_perturbation_ratio` | `avg_paraphrased_loss` |
  | `evaluate_util.py` | `get_kl_divergence` | KL 输出 |
  | `evals/eval_everything.py` | 同上两处镜像副本 | 同上 |

  `.float()` 是 bf16→fp32 的无损加宽，数值与旁边 `.tolist()` 行完全一致（已实测比对相等），**不影响指标**。注意别顺手把 loss 本身改成 fp32 计算——那会真的改变 `avg_gt_loss`、truth ratio、Forget Quality 的数值，使结果不再等同于一次纯 bf16 运行。
- **训练崩在评估阶段时不用重训**：检查点是训练结束时就落盘的，`save_dir/checkpoint-<步数>/` 里有完整的 safetensors 分片、tokenizer 和 DeepSpeed 状态。但要注意 `Model Utility` / `Forget Quality` / `aggregate_stat.txt` 的聚合逻辑写在 `dataloader.py` 的 `evaluate()` 里，`evaluate_util.py` 单跑只会产出每个任务的原始 JSON；聚合函数在 `utils.py`（`interleave_eval_result_dict` / `get_model_utility` / `get_forget_quality`），没有命令行入口，想只重跑评估需要自己写个几十行的驱动脚本。
- **`forget.yaml` 里 `eval.aggr_save_dir: ${..aggr_save_dir}` 是坏的**：根层没有 `aggr_save_dir` 这个键，一旦被访问就是 `InterpolationKeyError`。目前代码里没有任何地方读它，属于休眠状态，别去动。
- **日志里 `split_list` 打印成 `['retain_perturbed', ..., '${split}']` 不是 bug**：那是 OmegaConf 打印 ListConfig 时显示的未解析原文，按下标取值时会正常解析成 `forget05`。
- **`nvidia-smi` 没有任何输出、`torch.cuda.is_available()` 为 False**：GPU 没挂到容器上（本机出现过，后来恢复）。先解决卡的问题再开跑，否则 `torchrun` 会直接失败。
- **粘贴命令后报奇怪的参数错误**：多行 + `\` 续行的命令块整块粘进交互式终端时容易丢换行、把相邻两行拼起来。一次粘一条，或写进 `.sh` 文件用 `bash` 执行。
- **评估阶段 OOM**：下调 `forget.yaml` 的 `eval.batch_size`（如 4）；MUSE 下调 `--per_device_batch_size`。
- **磁盘写满**：系统盘只有 30GB。确认 `HF_HOME`、`save_dir`、`out_dir` 都在 `/root/autodl-tmp`；用 `df -h / /root/autodl-tmp` 对照。注意 `HUGGINGFACE_HUB_CACHE` 要写 `$HF_HOME/hub`。
- **model_path 报错找不到目录**：必须是本地目录，不能填 HF 仓库名；用 HF 缓存里的 `snapshots/<哈希>/` 目录（见 6.1）。
- **`TypeError: Object of type Column is not JSON serializable`**：`datasets>=3` 的行为变化，`MUSE/load_data.py` 已修，其它脚本遇到同类报错时把 `ds[col]` 包一层 `list(...)`。

## 11. 时间预估

相较论文 8 卡，2 卡吞吐约为其 1/4，墙钟时间约 **4 倍**。用 `accum=16` 对齐全局 batch 不会显著增加耗时，主要瓶颈是卡数。synthetic 分钟级；TOFU/MUSE/WMDP 均为 7B 模型、单机 2 卡，耗时同量级。
