# SimNPO 实验复现指南（2×A800-80GB）

本文档面向 **2 张 A800-80GB** 的机器，说明如何从零复现本仓库的四个子项目。目标：远程 `git pull` 后按步骤即可开跑。言简意赅，只列必要细节。方法本身的公式与代码对照见 [方法原理](方法原理.md)。

**推荐复现顺序：synthetic → TOFU → MUSE → WMDP**（由易到难、由快到慢：synthetic 分钟级验证环境，TOFU 为主实验，MUSE/WMDP 需额外数据或更长时间）。

---

## 1. 硬件与环境

- GPU：2×A800-80GB（7B 模型最少 2 张；1 张易 OOM）。**开跑前先 `nvidia-smi` 确认卡已挂载**，本机曾出现 `nvidia-smi` 无输出、`torch.cuda.is_available()==False` 的情况。
- 镜像：PyTorch 2.8 / Python 3.12 / CUDA 12.8（可直接复用，不必降级到 CUDA 11.8）。conda 只有 `base` 环境，四个子项目都在 `base` 里跑，不必再建 `muse` / `wmdp` 环境。
- 磁盘（实测）：

| 挂载点 | 容量 | 可用 | 用途 |
|--------|------|------|------|
| `/`（overlay，系统盘） | 30G | ~24G | 只放代码，**不要放权重/缓存/检查点** |
| `/root/autodl-tmp`（数据盘） | 300G | ~198G | 模型、HF 缓存、数据集、所有训练产出 |

- 显存占用（TOFU 训练）：约 55GB/卡；评估阶段峰值更高，已把 eval batch 调到 8

### 1.1 数据盘目录约定

```
/root/autodl-tmp/
├── env_hf.sh            # 环境变量脚本（见 1.2）
├── huggingface/         # HF_HOME：所有模型/数据集缓存
├── TOFU_results/        # TOFU 遗忘输出（forget.yaml 的 save_dir）
├── MUSE_data/           # ← 软链 MUSE/data
├── MUSE_ckpt/           # ← 软链 MUSE/baselines/ckpt
├── WMDP_files/          # data/ 放 bio 语料，results/ ← 软链 WMDP/files/results
├── WMDP_cache/          # ← 软链 WMDP/.cache
└── logs/                # 运行日志
```

仓库里这几个目录已经做成指向数据盘的软链（`MUSE/data`、`MUSE/baselines/ckpt`、`WMDP/.cache`、`WMDP/files/results`），所以代码里的相对路径不用改，写出来的字节自动落数据盘。

### 1.2 环境变量（每开一个新 shell 都要 source）

```bash
source /root/autodl-tmp/env_hf.sh
```

内容等价于：

```bash
export HF_ENDPOINT=https://hf-mirror.com                       # 必需：本机直连 huggingface.co 超时
export HF_HOME=/root/autodl-tmp/huggingface
export HUGGINGFACE_HUB_CACHE=/root/autodl-tmp/huggingface/hub
export TRANSFORMERS_CACHE=/root/autodl-tmp/huggingface/hub
export HF_TOKEN=...        # 脚本自动从仓库根目录 .env 的 HuggingFace_token 读取
export HUGGINGFACE_HUB_TOKEN="$HF_TOKEN"
```

> `HUGGINGFACE_HUB_CACHE` 必须是 `$HF_HOME/hub`。写成 `$HF_HOME` 会绕开已有的 90GB 缓存，导致模型全部重下。

## 5. synthetic（先跑，验证环境，单卡/分钟级）

数据本地生成、模型自建，无需下载任何权重，产出全在 `synthetic/{data,models,record}/`（已 gitignore）。

**注意：四个脚本的 argparse 默认值是 `state_size=9`、序列长度 `50/40/60`、样本数 `1000/500/500`，与 `run_synthetic.sh` 和仓库里已有的产物不一致。** 想复现已有结果，必须像下面这样把同一组数据参数传给每一步——参数不同会拼出不同的文件名，后一步就找不到前一步的产物。

```bash
cd synthetic

# 所有步骤共用的数据/模型参数（与 run_synthetic.sh 一致）
DATA="--state_size 10 --seq_length_retain 20 --seq_length_forget1 20 --seq_length_forget2 20 \
      --num_retain_sequences 10000 --num_forget_sequences1 5000 --num_forget_sequences2 5000 \
      --leakage 0.2 --data_dir data"
ARCH="--n_embd 128 --n_layer 4 --n_head 4 --activation softmax"
PRE="--batch_size 128 --epochs 5 --learning_rate 0.0005"

# 1) 生成合成数据 -> data/state_size_10_retain_20_10000_..._leakage0.2.pkl
python generate_data.py $DATA --seed 42 --test_size 0.2

# 2) 训练 pretrain 与 retain 参照模型 -> models/.../*_pretrain.pth、*_retain.pth
python train.py $DATA $ARCH $PRE --model_type pretrain --only_forget1 --seed 42
python train.py $DATA $ARCH $PRE --model_type retain --seed 42

# 3) 遗忘 -> models/.../*_unlearn.pth + record/.../record_kl_SimNPO_*.json
python unlearn.py $DATA $ARCH --pretraining_batch_size 128 --pretraining_epochs 5 \
  --pretraining_learning_rate 0.0005 --loss_type SimNPO --beta 1.0 \
  --unlearning_epochs 1 --max_iterations 50 --batch_size 4 --learning_rate 0.0005 \
  --seed 42 --use_retrain_eval

# 4) 评估任一模型（model_type 可选 pretrain / retain / unlearn）
python evaluate.py $DATA $ARCH $PRE --model_type retain
```

单卡即可（默认 `cuda:0`，加 `--no_cuda` 退回 CPU）。`unlearn.py` 支持的 `loss_type` 见 `unlearn_utils.py`：`NPO`、`NPO_KL`、`NPO_RT`、`SimNPO`、`SimNPO_KL`、`SimNPO_RT`、`grad_diff`、`grad_ascent`、`kl` 等。

遗忘过程中 forget/retain 两侧的 KL 曲线写在
`synthetic/record/<数据参数>/<模型参数>_unlearn/record_kl_<loss_type>_beta_*_iter_*_bs_*_lr_*_seed_*.json`，
自行读这个 JSON 画图即可。`run_synthetic.sh` 末尾调用的 `plot_evaluation.py` **上游没有随代码发布，本仓库里不存在**，别照抄那一段。

## 6. TOFU 主实验（2 卡）

### 6.1 下载起点模型（本机已完成，换机器才需要重跑）

不加 `--local-dir`，直接落到数据盘上的 `HF_HOME` 缓存，避免同一份 13GB 权重存两遍：

```bash
source /root/autodl-tmp/env_hf.sh

# 遗忘起点模型（~13GB，主实验唯一必需）
hf download locuslab/tofu_ft_llama2-7b
# tokenizer / 基座（只会拉 tokenizer 与 config，几 MB）
hf download NousResearch/Llama-2-7b-chat-hf
```

`forget.py` 用 `os.listdir(model_path)` 判断权重，**`model_path` 必须是本地目录，不能填 HF 仓库名**。缓存里的快照目录就是一个合法本地目录（里面是指向 blobs 的软链，`from_pretrained` 能正常读），拿它做 `model_path`：

```bash
ls -d $HF_HOME/hub/models--locuslab--tofu_ft_llama2-7b/snapshots/*/
# /root/autodl-tmp/huggingface/hub/models--locuslab--tofu_ft_llama2-7b/snapshots/8fa500e8f345f1dd9cfe95bb4689878c944c9cbd/
```

这个路径已经写进 `TOFU/config/forget.yaml`。换机器后快照哈希会变，用上面的 `ls -d` 取到真实路径再改 `model_path`。

> 想要一个干净独立的目录也可以 `hf download locuslab/tofu_ft_llama2-7b --local-dir /root/autodl-tmp/models/tofu_ft_llama2-7b`，代价是多占 13GB。
> 备选：从作者 [Google Drive](https://drive.google.com/drive/folders/1L47Hf813gal8RD581S3XrWHnY_0ll4y4?usp=sharing) 下载 origin 模型。

### 6.2 安装依赖

本机 `base` 环境已装好 `requirements.txt` 里的依赖（transformers 4.46.3 / datasets 5.0.1 / torch 2.8），**只差 `flash-attn`**：

```bash
cd TOFU
pip install -r requirements.txt                # 已装过可跳过
pip install flash-attn --no-build-isolation    # 若编译失败，见第 9 节
```

### 6.3 关键配置（`TOFU/config/forget.yaml`，已改好）

| 项 | 值 | 说明 |
|----|----|------|
| `model_path` | `/root/autodl-tmp/huggingface/hub/models--locuslab--tofu_ft_llama2-7b/snapshots/8fa500e8f345f1dd9cfe95bb4689878c944c9cbd` | HF 缓存里的快照目录（数据盘）；换机器后按 6.1 重新取哈希 |
| `save_dir` | `/root/autodl-tmp/TOFU_results/2GPU_<超参拼接>` | 输出必须在数据盘；**不要**改回 `${model_path}/unlearned/...`，那会把检查点写进 HF 缓存 |
| `batch_size` | 1 | 不变 |
| `gradient_accumulation_steps` | **16** | 2 卡下 `1×16×2=32`，与论文 8 卡 `1×4×8=32` 一致 |
| `num_epochs` | 10 | 不变 |
| `lr` | 1e-5 | 不变 |
| `forget_loss` | `simnpo_grad_diff` | SimNPO 主方法 |
| `eval.batch_size` | **8** | 由 30 降低，防评估 OOM |

> `num_epochs` 决定数据过几遍；全局 batch = `batch_size × accum × 卡数`。用 `accum=16` 保持全局 batch=32，使优化步数与论文一致。

### 6.4 运行（每次只跑一个场景）

```bash
cd TOFU
source /root/autodl-tmp/env_hf.sh

bash run_simnpo.sh forget05      # 默认即 forget05，可省略参数
# 查看结果满意后再跑：
bash run_simnpo.sh forget10
```

`run_simnpo.sh` 自身也会把 `HF_ENDPOINT` / `HF_HOME` / `HUGGINGFACE_HUB_CACHE` 默认指到数据盘，所以忘了 source 也不会写系统盘。

脚本默认 `CUDA_VISIBLE_DEVICES=0,1`、`nproc_per_node=2`、`master_port=29500`，可用环境变量覆盖；`npo_coeff`/`beta` 按 split 自动选择。等价手动命令：

```bash
# forget05
CUDA_VISIBLE_DEVICES=0,1 torchrun --nproc_per_node=2 --master_port=29500 \
  forget.py --config-name=forget.yaml split=forget05 npo_coeff=0.1375 beta=2.5
# forget10
CUDA_VISIBLE_DEVICES=0,1 torchrun --nproc_per_node=2 --master_port=29500 \
  forget.py --config-name=forget.yaml split=forget10 npo_coeff=0.125 beta=4.5
```

### 6.5 结果

- 遗忘后模型与评估写入 `/root/autodl-tmp/TOFU_results/2GPU_<超参拼接>/`
- 汇总指标：该目录下 `checkpoint*/aggregate_stat.txt`（Forget Quality 依赖 `TOFU/data/retain95_llama_wd0.01/.../eval_log_aggregated.json`，仓库已自带）
- 数据盘上还留着 7 月底几次历史运行的结果，目录名里的 `accum5`/`accum6` 是当时的多卡设置，与现在的 `accum16`（2 卡）区分开看

### 7.2 运行 unlearning（SimNPO+GDR，论文设定）

tokenizer 用公开镜像 `NousResearch/Llama-2-7b-hf`，避开门控的 `meta-llama/Llama-2-7b-hf`：

```bash
cd MUSE/baselines
source /root/autodl-tmp/env_hf.sh

# News
CUDA_VISIBLE_DEVICES=0,1 python unlearn.py --algo simnpo_gdr \
  --model_dir muse-bench/MUSE-News_target \
  --tokenizer_dir NousResearch/Llama-2-7b-hf \
  --data_file ../data/news/raw/forget.txt \
  --retain_data_file ../data/news/raw/retain1.txt \
  --out_dir ./ckpt/news/simnpo_gdr \
  --max_len 2048 --epochs 10 --lr 1e-5 \
  --per_device_batch_size 4 --beta 0.7 --coeff 0.1 --npo_coeff 1.0

# Books
CUDA_VISIBLE_DEVICES=0,1 python unlearn.py --algo simnpo_gdr \
  --model_dir muse-bench/MUSE-Books_target \
  --tokenizer_dir NousResearch/Llama-2-7b-hf \
  --data_file ../data/books/raw/forget.txt \
  --retain_data_file ../data/books/raw/retain1.txt \
  --out_dir ./ckpt/books/simnpo_gdr \
  --max_len 2048 --epochs 10 --lr 1e-5 \
  --per_device_batch_size 4 --beta 0.75 --coeff 0.1 --npo_coeff 1.0
```

`--algo` 可选：`simnpo`、`simnpo_gdr`、`ga`、`ga_gdr`、`ga_klr`、`npo`、`npo_gdr`、`npo_klr`、`tv`。

`--model_dir` / `--tokenizer_dir` 填仓库名即可，权重已在数据盘的 `HF_HOME` 缓存里，不会重下。`--out_dir ./ckpt/...` 也不用改：`MUSE/baselines/ckpt` 是指向 `/root/autodl-tmp/MUSE_ckpt` 的软链，检查点自动落数据盘（每个 epoch 一个 13GB 检查点，跑满 10 epoch 前留够空间）。

## 9. 常见问题

- **下载卡住 / `ReadTimeoutError` / 连不上 huggingface.co**：本机直连 HF 不通，必须 `source /root/autodl-tmp/env_hf.sh` 让 `HF_ENDPOINT=https://hf-mirror.com` 生效。镜像偶发超时会自动重试。
- **`ModuleNotFoundError: flash_attn`（本机当前就是这个状态）/ flash-attn 编译失败**：`pip install flash-attn --no-build-isolation`；不想编译就把 `TOFU/config/model_config.yaml` 里 `llama2-7b.flash_attention2` 设为 `"false"`（可跑，略慢）。
- **`nvidia-smi` 没有任何输出、`torch.cuda.is_available()` 为 False**：GPU 没挂到容器上，先解决卡的问题再开跑，否则 `torchrun` 会直接失败。
- **评估阶段 OOM**：下调 `forget.yaml` 的 `eval.batch_size`（如 4）；MUSE 下调 `--per_device_batch_size`。
- **磁盘写满**：系统盘只有 30GB。确认 `HF_HOME`、`save_dir`、`out_dir` 都在 `/root/autodl-tmp`；用 `df -h / /root/autodl-tmp` 对照。注意 `HUGGINGFACE_HUB_CACHE` 要写 `$HF_HOME/hub`。
- **model_path 报错找不到目录**：必须是本地目录，不能填 HF 仓库名；用 HF 缓存里的 `snapshots/<哈希>/` 目录（见 6.1）。
- **`TypeError: Object of type Column is not JSON serializable`**：`datasets>=3` 的行为变化，`MUSE/load_data.py` 已修，其它脚本遇到同类报错时把 `ds[col]` 包一层 `list(...)`。

## 10. Llama-2 访问受限（申请被拒）怎么办

被拒的通常是 Meta 官方 `meta-llama/Llama-2-...`，**本仓库不需要它**：

- TOFU 起点 `locuslab/tofu_ft_llama2-7b` 公开且**自带 tokenizer**；若 `NousResearch/Llama-2-7b-chat-hf` 也下不了，把 `TOFU/config/model_config.yaml` 的 `llama2-7b.hf_key` 改成本地目录，例如 `$HF_HOME/hub/models--locuslab--tofu_ft_llama2-7b/snapshots/<哈希>`。本机这两个仓库都已下好，不用改。
- MUSE 的 `--tokenizer_dir` 用公开镜像 `NousResearch/Llama-2-7b-hf` 替代 `meta-llama/Llama-2-7b-hf`。

## 11. 时间预估

相较论文 8 卡，2 卡吞吐约为其 1/4，墙钟时间约 **4 倍**。用 `accum=16` 对齐全局 batch 不会显著增加耗时，主要瓶颈是卡数。synthetic 分钟级；TOFU/MUSE/WMDP 均为 7B 模型、单机 2 卡，耗时同量级。
